# Phase 2 — Diagnosis and Plan

For each material task, distinguish symptoms from root causes before changing code.

## Plan contents

- objective and acceptance criteria
- affected files/components
- dependency order
- implementation steps
- anti-pattern constraints from current research
- test strategy
- integration/runtime checks
- rollback or partial-failure handling
- strategy alternatives when architectural choice is material

For debugging, state the most likely root cause and the evidence supporting it. For migration work, define compatibility and rollback boundaries before changing data or contracts.

Do not begin implementation until the plan contains a concrete verification method for each material step.
